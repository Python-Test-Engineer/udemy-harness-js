07

The door

The dispatcher
always returns a string.

src/tools.jsrunTool (condensed) 
export async function runTool(name, rawArgs, ctx) {
  if (!HANDLERS[name]) return 'ERROR: unknown tool';
  const { args, error } = validate(name, rawArgs);
  if (error) return error;
  try {
    return await HANDLERS[name](ctx.workspace, args, ctx);
  } catch (err) {
    return 'ERROR: ...'; // never throw into the loop
  }
}
four jobs, in order
1look up the tool
2validate the arguments
3run the handler
4catch everything → text
what the model reads back
ERROR: unknown tool "read_fiel". Available: list_files, read_file, ...
ERROR: "limit" must be a integer, got string
FORBIDDEN: SAVE ../escape.txt - path escapes the workspace
A thrown error would end the run. A returned error is an observation the model can recover from.

One task after another

A session is the loop,

src/cli.jstrimHistory
export function trimHistory(messages, max = MAX_HISTORY) {
  const kept = (messages ?? []).filter((m) => m.role !== 'system');
  let start = Math.max(0, kept.length - Math.max(0, max));
  // never start on a tool result: the provider rejects it
  while (start < kept.length && kept[start].role !== 'user') start += 1;
  return start >= kept.length ? [] : kept.slice(start);
}
🔁
The step budget resetsevery task starts at step 1 of its own 12
🧵
History is carriedso "now add tests" knows what was just built
🧼
The system prompt is rebuilta memory saved last task is already visible
The cut lands on a user turn because a provider rejects a history that starts with a tool result or ends with an unanswered tool call.
